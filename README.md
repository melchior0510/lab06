## Хэсэг A: Category-Partition гараар — Шилжүүлгийн функц

### Олон алдааны давуу эрэмбэ (oracle-ийн үндэс)

Нэг хүсэлтэд хэд хэдэн алдаа зэрэг байвал **from → to → amount** дарааллаар шалгана гэж тогтоов. Amount-ийн дотор: `BAD_AMOUNT → INSUFFICIENT → LIMIT`. Үндэслэл: тодорхойлолтын алдааны жагсаалт энэ дарааллаар бичигдсэн бөгөөд "эх үүсвэр данс → хүлээн авагч данс → дүн" гэж шалгах нь шилжүүлгийн бодит урсгалд (эхлээд данс байгаа эсэхийг, дараа нь дүнг шалгах) тохирно. Дүнг шалгахдаа эхлээд утга өөрөө хүчинтэй эсэх (>0), дараа нь үлдэгдэл, хамгийн сүүлд өдрийн лимитээр шалгана.

### A1 — Параметр, сонголт, төлөөлөх утгууд

| Параметр | Сонголт (choice) | Төлөөлөх утга | Тайлбар |
|---|---|---|---|
| **from** | Данс байгаа эсэх / төлөв | `Valid` — байгаа, царцаагдаагүй | Үлдэгдэл 1000 |
| | | `Frozen` — байгаа, царцаагдсан | |
| | | `Missing` — системд байхгүй ID | |
| **to** | Данс байгаа эсэх / from-той харьцаа | `Valid` — байгаа, from-оос өөр | |
| | | `Missing` — байхгүй ID | |
| | | `SameAsFrom` — from-той ижил ID | |
| **amount** | Дүн ба үлдэгдэл/лимитийн харьцаа | `Normal` — 0 < дүн < үлдэгдэл, лимитийн дотор | |
| | | `ExactBalance` — дүн = үлдэгдэл яг тэнцүү | Хязгаарын утга ("хэтрэхгүй" гэдэгт тэнцүү зөвшөөрөгдөнө) |
| | | `Zero` — дүн ≤ 0 (0, -5 нэг анги) | |
| | | `OverBalance` — дүн > үлдэгдэл | |
| | | `OverLimit` — дүн ≤ үлдэгдэл боловч өдрийн лимитээс хэтэрсэн | |
| **currency** | Дансны валюттай харьцаа | `Same` — дансны валютаар | |
| | | `Different` — өөр валют → ханшийн хөрвүүлэлт | |

**Далд орчны сонголтууд** (хүсэлтэд харагдахгүй, setup-д бэлдэх зүйлс):

- **Өдрийн лимит хэр дүүрсэн байсан бэ** — `OverLimit`-ийг үүсгэхийн тулд лимитийг үлдэгдлээс бага (эсвэл өдрийн өмнөх шилжүүлгээр дүүрсэн) болгож бэлдэнэ. Ийм учраас лимитийн төлөв нь тусдаа параметр биш, `amount`-ийн `OverLimit` утгын setup болгон шингээв.
- **Ханшийн хүснэгт / дансны валют** — `Different` үед шалгалтыг хөрвүүлсний дараах дүнгээр хийнэ. Тиймээс `OverBalance + Different` хослолд дүн тоон утгаараа үлдэгдлээс бага боловч хөрвүүлсний дараа хэтэрдэг тохиолдол орно.
- **Дансны үлдэгдэл** (1000) ба **өдрийн лимит** (жишээ нь 5000; `OverLimit`-д 300 болгож бууруулна).

### A2 — Хязгаарлалтууд

| Утга | Тэмдэглэгээ | Нэг өгүүлбэр үндэслэл |
|---|---|---|
| from=`Frozen` | `[ERROR]` | Царцаагдсан данснаас шилжүүлэх нь `ERROR_FROZEN` буцаадаг алдааны анги; to/amount алдаатай хослуулбал үүнийг нууж (masking) орхидог тул хослуулахгүй. |
| from=`Missing` | `[ERROR]` | `ERROR_NO_FROM` — эхний шалгалтаар зогсдог тул to/amount-ийн утгыг шалгах боломжгүй, зөвхөн хүчинтэй to + Normal-тай хослуулна. |
| to=`Missing` | `[ERROR]` | `ERROR_NO_TO` — from хүчинтэй үед л хүрнэ; amount алдаа нь to-ийн алдаагаар далдлагдана. |
| to=`SameAsFrom` | `[ERROR]` `[IF from=Valid]` | `ERROR_SAME_ACCOUNT`; from Frozen/Missing үед "from-той ижил" гэдэг утга учиргүй (from-ийн алдаа түрүүлнэ) тул from=Valid байх үед л. |
| amount=`Zero` | `[ERROR]` `[IF from=Valid, to=Valid]` | `ERROR_BAD_AMOUNT`; from/to-ийн алдаа түрүүлдэг тул хоёр данс хүчинтэй үед л хүрнэ. |
| amount=`OverBalance` | `[ERROR]` `[IF from=Valid, to=Valid]` | `ERROR_INSUFFICIENT`; дансны шалгалт давсны дараа л хүрнэ. |
| amount=`OverLimit` | `[ERROR]` `[IF from=Valid, to=Valid]` | `ERROR_LIMIT`; хамгийн сүүлийн шалгалт. |
| amount=`ExactBalance` | `[SINGLE]` `[IF currency=Same]` | Хязгаарын утга нэг удаа шалгахад хангалттай (бүх сонголттой нь үржүүлэх шаардлагагүй), хөрвүүлэлтийн нөлөөг холихгүйн тулд `Same` валюттай. |
| currency=`Different` | — | Алдаа биш, `OK` үр дүнтэй; `ExactBalance`-аас бусад бүх хүчинтэй хослолтой хослуулна. |

Хязгаарлалтыг PICT хэлээр бичвэл:

```
IF [From] <> "Valid" THEN [To] = "Valid" AND [Amount] = "Normal";
IF [To]   <> "Valid" THEN [Amount] = "Normal";
IF [Amount] = "ExactBalance" THEN [Currency] = "Same";
```

**"N → M" тооцоо (бүрэн олонлог → хязгаарлалтын дараа):**

Бүрэн олонлог = 3 (from) × 3 (to) × 5 (amount) × 2 (currency) = **90**.

Хязгаарлалтын дараа:

- from=`Valid`, to=`Valid`: amount 5 × currency 2 = 10, гэхдээ `ExactBalance`-ийн `Different` хувилбар хасагдана (SINGLE) → **9**
- from=`Valid`, to=`Missing`: amount=`Normal` × currency 2 = **2**
- from=`Valid`, to=`SameAsFrom`: amount=`Normal` × currency 2 = **2**
- from=`Frozen`, to=`Valid`, amount=`Normal`: currency 2 = **2**
- from=`Missing`, to=`Valid`, amount=`Normal`: currency 2 = **2**

Нийт 9 + 2 + 2 + 2 + 2 = **90 → 17**. (Python-оор 90 хослол бүрийг шүүж 17 гэдгийг давхар шалгав.)

## Хэсэг B: PICT — pairwise covering array

PICT-ийг `~/tools/pict`-д (репогийн гадна) эх кодоос бүтээсэн, нотолгоо: `results/pict-build.txt` (`pict commit ab76c25`). Бүх команд `/r`-гүй, анхдагч тохиргоотой ажилласан тул дахин ажиллуулахад ижил үр дүн гарна. Доорх мөрийн тоо бүр `tail -n +2 results/<файл> | wc -l` (толгой мөргүй) тоотой таарна.

### B1 — Browser жишээ (`browser.model`)

| Хувилбар | Файл | Мөрийн тоо |
|---|---|---|
| 2-way (pairwise) | `results/browser-2way.txt` | **10** |
| 3-way (`/o:3`) | `results/browser-3way.txt` | **20** |
| Бүрэн олонлог | 3 × 3 × 2 × 2 × 2 × 2 | 144 |

**Greedy-гийн тайлбар.** Лекц дээр гараар 9 мөрөнд багтаасан бол PICT 10 мөр өгсөн, өөрөөр хэлбэл 1 мөр илүү. PICT нь greedy алгоритм ашигладаг: мөр бүрт одоогоор хамрагдаагүй хосыг хамгийн их хамарсан мөрийг шууд сонгодог бөгөөд өмнөх сонголтоо буцааж өөрчлөхгүй. Тиймээс бүх хосыг хамарсан гэдгийг баталгаажуулдаг ч хамгийн цөөн мөрийг олно гэдгийг баталдаггүй (хамгийн бага covering array олох нь NP-хүнд бодлого). Гараар бодохдоо хүн бүхэл бүтэн хүснэгтийг харж хосуудыг төлөвлөн хуваарилдаг тул 9 хүртэл цөөрч болно. 3-way нь 144-ийн 20 мөр буюу ойролцоогоор 14%-д багтсан нь гурвалсан харилцан үйлчлэлийг хамарсан ч бүрэн олонлогоос хавьгүй бага.

### B2 — Шилжүүлгийн модель

Дөрвөн параметр (From, To, Amount, Currency). Хэсэг A-гаас нэг өөрчлөлт: `Amount`-д хязгаарын утга `ExactBalance`-ийг нэмсэн (5 утга). Моделууд: `transfer-nc.model` (хязгаарлалтгүй), `transfer.model` (A2-ын хязгаарлалттай), `transfer-neg.model` (алдааны утгад `~`).

| Хувилбар | Файл | Мөрийн тоо | Happy path мөр (бүх утга хүчинтэй) | Нэг мөр дэх алдааны тоо |
|---|---|---|---|---|
| Хязгаарлалтгүй | `transfer-nc.txt` | **15** | 0 | 1–3 (1: 5 мөр, 2: 6 мөр, 3: 4 мөр) |
| Хязгаарлалттай (A2) | `transfer.txt` | **15** | 1 | 0–1 (ихдээ 1) |
| Сөрөг утгатай (`~`) | `transfer-neg.txt` | **18** | 3 | 0–1 (ихдээ 1) |

(Бүрэн олонлог 90, A2-ын хязгаарлалтын дараа 17.)

**Гаралтыг уншсан дүгнэлт:**

- **Хязгаарлалтгүй:** happy path мөр **гарсангүй**: 15 мөр бүрт дор хаяж нэг алдаа байна, 4 мөрөнд 3 алдаа зэрэг (жишээ нь `Frozen, SameAsFrom, Zero`). Ийм мөрөнд эхний алдаа (`ERROR_FROZEN`) бусдыг нууна (error masking) тул `SameAsFrom`, `Zero` нь бодитоор шалгагдаагүй. Pairwise хамралтын хувьд хос "хамрагдсан" боловч алдааны семантикийн хувьд хоосон.
- **Хязгаарлалттай:** `transfer.txt`-д алдаа зэрэг орохыг хязгаарлалтаар хориглосон тул мөр бүр ≤ 1 алдаатай. Happy path гэх 1 мөр байгаа боловч энэ нь `ExactBalance` (Normal биш).
- **`~` хэрэглэсэн:** PICT нэг мөрөнд ≤ 1 сөрөг утга оруулдаг (3 happy path, бусад нь яг 1 алдаатай) тул A2-ын "алдаа хослуулахгүй" хоёр хязгаарлалтыг (`From`/`To` алдаатай бол бусад нь Normal) орлоно. Харин **`ExactBalance`-ийн SINGLE хязгаарлалт хэвээр хэрэгтэй** (`~` нь ердийн утгын хослолыг хязгаарладаггүй, мөн `Currency`-тэй хольбол шалгаж буй зүйл тодорхойгүй болно), тиймээс `transfer-neg.model`-д энэ нэг хязгаарлалт үлдсэн. Тэнд ч `ExactBalance` нь `Different`-тэй хэзээ ч орохгүй. Үүний үр дүнд хязгаарлалтын тоо 3 → 1 болсон.
- Мөрийн тоо: 15 → 18 нь зөвхөн тоо биш, **алдаа бүр өөрийн мөртэй болсон** гэсэн үг (сөрөг утга бүр заавал нэг мөрөнд орох ёстой, мөн хоорондоо хослохгүй).

### B2 (үргэлжлэл) — Гаралтаас 4 бодит тест кейс (Лаб 5 хэв маяг)

Дансны ерөнхий setup: данс A (from) үлдэгдэл 1000 MNT, өдрийн лимит 5000, данс B (to) оршин байна; ханш 1 USD = 3500 MNT.

| # | Эх мөр | Setup | Оролт (`POST /transfer`) | Oracle |
|---|---|---|---|---|
| TC1 (**happy path**) | `transfer-neg.txt` мөр 1: `Valid, Valid, Normal, Different` | A-д 1000 MNT, B байгаа | `{"from":"A","to":"B","amount":0.1,"currency":"USD"}` (=350 MNT) | **201** `{"result":"OK"}` |
| TC2 (**neg, 1 алдаа**) | `transfer-neg.txt` мөр 4: `Valid, Valid, ~OverBalance, Same` | A-д 1000 MNT, лимит 5000 | `{"from":"A","to":"B","amount":1500,"currency":"MNT"}` | **200** `{"result":"ERROR_INSUFFICIENT"}` |
| TC3 (**neg, 1 алдаа**) | `transfer-neg.txt` мөр 14: `~Frozen, Valid, ExactBalance, Same` | A царцаагдсан, үлдэгдэл 1000 | `{"from":"A","to":"B","amount":1000,"currency":"MNT"}` | **200** `{"result":"ERROR_FROZEN"}` |
| TC4 (**олон алдаатай**) | `transfer-nc.txt` мөр 4: `Frozen, SameAsFrom, Zero, Different` | A царцаагдсан | `{"from":"A","to":"A","amount":0,"currency":"USD"}` | **200** `{"result":"ERROR_FROZEN"}` — давуу эрэмбэ from → to → amount тул `FROZEN` нь `SAME_ACCOUNT`, `BAD_AMOUNT`-аас түрүүлнэ. |

TC3-т `ExactBalance` дүнтэй хослуулсан нь зориудын: хэрэв царцаалт шалгагдаагүй бол дүн нь үлдэгдэлтэй тэнцүү тул шилжүүлэлт амжилттай болох байсан, тиймээс `ERROR_FROZEN` нь зөвхөн царцаалтаас шалтгаалж байгааг баталгаажуулна.

### B3 — Гараар (A3) ба PICT-ийн харьцуулалт

| | Гараар (A3) | PICT |
|---|---|---|
| **Алдааны семантик** | Давуу эрэмбээр oracle-ийг мөр бүрт зориуд тодорхойлсон, давхар нөхцөл (мөр 11–14) оруулсан | Өөрөө oracle өгдөггүй; хязгаарлалт эсвэл `~`-гүйгээр олон алдаа хольж masking үүсгэнэ |
| **Хосын хамрал** | Баталгаагүй: хос орхигдсоныг мэдэхгүй | Бүх хосыг баталгаатай хамарна (3-way хүртэл) |
| **Тоо** | 14 мөр, ухаалгаар сонгосон | 15–18 мөр, greedy тул хамгийн цөөн биш |
| **Happy path** | Заавал оруулсан | Хязгаарлалтгүйд огт гарахгүй байж болно |
| **Хүчин чармайлт** | Бодох ихтэй | Модель бичсэний дараа автомат |

Гараар хийсэн хүснэгт алдааны семантикийг (ямар алдаа ямар шалтгаанаар, ямар эрэмбээр) илүү сайн барьдаг, харин PICT хослолын хамралтыг системтэй баталгаажуулдаг. Хамгийн сайн нь хоёрыг хослуулах: category-partition-аар утга, хязгаарлалт, oracle-оо гараар тодорхойлж, PICT-ээр хослолыг үүсгэх.

## Дүгнэлт

Category-partition нь тест дизайныг "ямар сонголт, ямар утга, ямар хязгаарлалт" гэсэн бүтэцтэй асуудал болгон хувиргаж, код байхгүй үед ч (спецификацаас) тест гаргах боломж олгосон. PICT нь үүнийг автоматжуулж, хязгаарлалтгүй 90 хослолыг 15 мөрөнд багтаасан боловч хязгаарлалтгүйгээр ажиллуулахад happy path огт гарахгүй, 3 алдаа нэг мөрөнд хольсон мөр гарч error masking-ийг харуулсан. `~` тэмдэглэгээ нь [ERROR] тэмдэглэгээтэй яг дүйх бөгөөд олон хязгаарлалтыг 1 болгон цөөрүүлсэн ч SINGLE-ийн хязгаарлалт хэвээр хэрэгтэй. PICT-ийн greedy шинж чанар нь 9 биш 10 мөр өгсөнөөр илэрсэн: хос бүрийн хамралтыг баталгаажуулдаг ч хамгийн цөөн мөрийг биш. Гараар хийсэн хүснэгт oracle-ийг (давуу эрэмбэ) тодорхойлдог, PICT үүнийг хийдэггүй тул хоёр арга бие биеийг нөхнө. Хамгийн их бодол шаардсан алхам нь олон алдааны давуу эрэмбийг тогтоох ба тэр эрэмбээс хязгаарлалт, oracle хоёулаа хамаарах тул A2 ба B2-ын бүх шийдвэр түүнээс эхэлсэн.
